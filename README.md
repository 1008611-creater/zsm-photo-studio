# AI 场景写真创作产品（工作名：取景簿）

> 面向国内创作者的 AI 场景写真网站：把地点、人物和镜头编排成用户真正想要的照片、视频及社媒素材。产品工作名建议“取景簿”，尚未做商标、域名或平台重名核验。

项目关系：ANS（`ans.cauai.fun`）是 AI 社区，本项目计划作为学生创业项目入驻/展示；新产品独立命名，目标产品域名为 `zsm.cauai.fun`。入驻方式、社区页面结构与域名配置尚未实施。

## 先说结论

方向值得验证，首发目标按用户要求定为一套完整收费产品：**选择真实/预设场景 → 布置人物与穿搭 → 导演台编排镜头 → 生成照片和短视频 → 导出小红书优先的发布素材包**。旅行、情侣写真和穿搭构成首发内容模板；Cosplay、婚纱写真、摄影及自媒体需求纳入后续扩展。研发可按技术依赖分阶段，但各环节要汇入同一套完整的用户产品与收费闭环。

Arnis 负责地理数据转 Minecraft 方块世界的设想有视觉记忆点，但它不是现成的摄影级 3D 引擎。需要先验证输出格式、几何材质、授权、目标机器/浏览器性能，再决定复用、改造或只借鉴其地理数据处理逻辑。不能假定 Minecraft 世界能直接成为逼真、可商用的摄影场景。

## 推荐推进顺序

1. 确认代码仓库、开源无线画布、导演台和生成服务的具体入口与授权。
2. 先做一次小范围技术验证：某一真实地点的数据 → 轻量 3D/灰白模场景 → 摄影机与人物代理摆位 → 一段可导出的镜头预演。
3. 做场景拍摄工作台 MVP，不先做大而全的生成模型市场或多平台自动发布。
4. 用少量目标用户验证作品质量、生成时间和付费意愿，再确定正式模型与算力架构。
5. MVP 和上线验收通过后，才讨论公网部署、GitHub 发布、收费与推广。

本目录的 Markdown 均为可修订的计划与执行提示词，不是已实施能力、采购授权或对外发布授权。目标是形成一套体验完整、可以公开收费的首发产品；阶段划分用于控制依赖和验收，不表示只交付零散 Demo。
