# 阶段 14：图片结果临时交付闭环

日期：2026-10-02（Asia/Shanghai）

## 本阶段完成

- OpenLux 成功响应不再把供应商原始 URL 或 Base64 直接交给浏览器。
- 服务端为每个结果建立进程内短期登记，生成 `/api/image-result?token=…` 临时交付链接。
- 临时链接默认 15 分钟有效；服务重启、过期或登记被清理后返回明确的 410，需要重新生成。
- 结果代理限制为 HTTPS 图片来源，拒绝本地/私网地址，限制响应体 16 MB，并设置 `no-store` 与 `nosniff`。
- 支持浏览器预览和“下载临时结果”；下载不会变成长久保存或云端作品库。
- Base64 结果仅在服务端内存中短暂登记，响应中不再带出 Base64。
- 当前仍不保存用户原图、提示词原文、渠道密钥或长期作品文件。

## 明确边界

- 登记是单进程内存语义，不是数据库、对象存储或跨设备历史；生产多实例部署前必须替换为有 TTL、权限和删除策略的存储层。
- OpenLux 原始 URL 可能比本地 15 分钟 TTL 更早失效；代理会返回“重新生成”的可操作错误。
- 当前接口不会自动刷新、批量重试或扣费；真实调用仍由服务端开关和页面费用确认共同控制。
