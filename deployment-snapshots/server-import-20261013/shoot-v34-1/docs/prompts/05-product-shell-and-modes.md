# Prompt 05 — zsm 产品子页面与快速/专家双模式

基于 `docs/product-route-and-modes.md`、`docs/cozyclay-audit.md` 和当前仓库事实，实现 zsm-photo-studio 的统一产品壳层与双模式工作流。

## 硬约束

- 仓库保持为 `zsm-photo-studio`；产品子路径按 `/studio` 设计。
- 保留所有用户改动；不修改 Arnis、无线画布、Toonflow 或 ANS 上游项目。
- 不部署、不 commit、不 push；不调用真实图片/视频模型、导演台、支付或社媒接口。
- 真实服务、凭证、账户和权限尚未提供的部分继续使用明确标记的 Mock/disabled，不猜 endpoint。

## 实现要求

1. 在现有 Next.js 应用中加入 `/studio` 产品壳层，视觉延续当前工作台；不要另起一个孤立的 demo 页面。
2. 增加快速模式和专家模式切换：
   - 快速模式默认进入，面向模板化旅行、情侣写真、穿搭流程；
   - 专家模式展示完整场景、人物、摄影机、镜头、画幅和导出控制；
   - 切换模式不得丢失当前本地草稿、镜头或任务状态；
   - 未实现的高级能力必须显示“待配置/Mock”，不能隐藏成已完成。
3. 将首发模板定义为可版本化数据，不把模板字段写死在页面组件；每个模板包含来源、许可状态、适用画幅、镜头预设和提示词块。
4. 快速模式复用现有 `GenerationRequest` 与 Mock provider；结果卡显示 Mock、来源、规格、许可和成本未知。
5. 专家模式复用现有 `SceneDocument`、镜头编辑、JSON/HTML 导出；为未来 CozyClay 接入保留独立 adapter，不把 CozyClay JSON 变成核心合同。
6. 完善空态、加载、失败、重试、无结果、能力未配置和模式切换提示；键盘可操作、移动端 360px/390px 无横向溢出。
7. 模式切换只属于产品体验层，不把前端按钮当作真实权限系统；在文档中写清未来服务端鉴权位置。

## 验收

- 新用户可在 3 分钟内从 `/studio` 选择模板并完成 Mock 图片流程。
- 专家用户可在 10 分钟内完成场景/人物/镜头编辑并导出拍摄沟通包。
- 快速 → 专家 → 快速切换后草稿保持一致。
- 桌面和手机浏览器主路径通过；运行 typecheck、lint、测试和 production build。
- 只读检查 diff，确认没有真实服务请求、凭证、部署或上游项目改动。

完成后汇报实际改动、验证证据、仍为 Mock/disabled 的能力，以及 CozyClay 和 Openlux 联调前最小资料清单。
