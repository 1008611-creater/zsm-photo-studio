# 模型、画布与 Arnis 接入策略

## 先验证服务，不以型号名驱动架构

Image2.5、MJ、Seedance2.5 等名称在需求中作为用户的偏好候选保留。公开/账户侧的实际可用型号、访问条件、API、商用条款、计费和输出权利必须在接入当日由用户或官方文档验证；型号数字相近不等于接口可调用。方案采取 provider adapter，不把单一名称写入核心业务模型。

## 生成能力分层

1. **确定性场景层**：地图、高程、建筑或用户提供资产生成可编辑场景；模型只做补充，不让文生图替代坐标准确性。
2. **人物与风格概念层**：先输出参考概念图/Look，不宣称照片级同一人或可动画数字替身。允许用户用自有或明确授权素材。
3. **图生视频/镜头预演**：选定关键帧与 shot card 后送到视频供应商；目标短镜头、镜头气氛与社媒竖屏片段。保留人工选片与重试。
4. **文案层**：平台标题、正文、标签作为草稿，按用户提供的品牌语气生成，不承诺曝光或代发。

## 供应商评估卡（每个候选都填）

- 官方产品/开发者入口与当前实际可用模型名称；用户的地区与账户能否调用。
- API 或可自动化方式；输入图、图像编辑、参考人物、视频首尾帧、时长、分辨率、画幅、队列限制。
- 商用许可、输入/输出权利、模型训练使用、数据保留、肖像/人脸限制、内容政策。
- 单位价格、失败是否收费、速率限制、并发、排队时间、可用性和回调机制。
- 画面一致性、中文字、手/服饰、真实人物稳定性、角色版权与水印等样本实测。
- 替代方案、降级体验和地区切换限制。

## 与用户无线画布的集成

优先把用户已部署的开源画布当作独立创作/执行服务，通过经过核实的 HTTP API、队列或导入导出格式连接。本产品保存“工作流模板版本 + typed input/output”，不在首发重造节点编辑器。需要用户提供 fork/仓库、部署方式（可打码域名）、已存在 API 文档、认证方式种类（绝不能贴密钥）、GPU 所有权与并发限制。

## Arnis 验证实验

1. 给出 Arnis 正确源码 repo/tag/commit 与其 license、依赖数据许可。
2. 用一个用户有权处理的街区范围构建世界，量化 OSM/高程覆盖、遗漏、转换时间、输出格式、几何/纹理颗粒度。
3. 测试能否导出/转换为 glTF/GLB 或其他合适格式，规模、朝向、高程基准和材质是否保留；不满足时保留独立管线。
4. 在目标浏览器渲染，测首屏载入和 FPS；为室内/布景/不可公开场所提供概念场景替代。
5. 核验许可证要求和外部地图数据 attribution；为每个资产写来源与用途字段。

实验是采用决策，不是必须复用 Arnis。Minecraft 世界可以是标志性风格预览/游戏化探索层，但未验证前不承诺为最终摄影渲染的几何主源。
