# Prompt 01 — 架构决策与可运行骨架

基于阶段 0 的已验证报告和用户认可的产品蓝图，在已确认的产品仓库中实现完整产品架构与可运行创作工作台。它是完整收费首发的基础，不应以占位骨架作为交付终点。先读取 repo 指令与 git 状态；保留所有用户现有改动；若仓库技术栈/部署与草案不同，以 repo 事实为准并解释偏差。不得重写用户未指定的项目或擅自创建远程仓库。

交付：

1. 更新一页架构决策记录：模块边界、三维场景引擎选择及测试理由、scene document 版本策略、任务队列、服务端密钥边界、对象存储、与现有无线画布/导演台的接口边界。
2. 以单体/模块化服务优先；仅在现有部署需要时增服务。列出目录结构、数据模型、错误与任务状态。
3. 建立响应式产品主流程，并明确哪些能力使用真实服务、哪些暂用 demo/mock；结构应覆盖项目/场景/人物/导演台/镜头/图像视频生成/作品交付/账户额度，而不是止于占位视口。
4. 通过 mock adapter 和契约类型保持后续供应商可替换；未验证 endpoint 不可硬编码。
5. 提供安装/开发/测试/构建步骤，并运行仓库适用的类型检查、测试与构建。

验收：此阶段产出能持续建设完整收费产品的架构与真实主流程切片；demo 数据须明确标识；桌面及手机布局可用；没有把模型 key 放浏览器；lint/typecheck/build 通过。列出后续整合完成定义，不能声称产品已成熟或已上线。报告文件清单、实际验证结果和待用户决定事项。不得 commit、push、部署或购买服务。
